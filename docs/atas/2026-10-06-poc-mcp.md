## Respostas às 4 perguntas

**P1. Claude app e Claude Code dividem a conexão?** Depende de como o Claude Code entra. Pelo conector do claude.ai (variante B), sim: mesmo token, mesma conexão. Pelo `claude mcp add` (variante A), não: é outro cliente OAuth, e com a regra "uma conexão por assistente" ele derruba o app. Como os devs vão usar o Claude Code pelo terminal, no projeto, a variante A é o caso real.
**Decisão proposta para o B8 e o F8:** o Claude Code vira o **quarto assistente** (`ai_assistants.slug = claude_code`, canal `ia:claude_code`), com cartão próprio em *Conexões de IA*. O servidor distingue os dois com segurança razoável sem CIMD: o app chega com redirect `https://claude.ai/api/mcp/auth_callback`; o Claude Code, com redirect `localhost` e `client_name` começando por "Claude Code". Semente da fatia 1: Claude, Claude Code, Codex, ChatGPT (este último condicional à parte 2).

**P2. Como cada assistente se identifica, e isso prova identidade?** Nesta rodada o servidor só anunciava registro dinâmico, e os dois clientes da Anthropic usaram isso: nome declarado, sem `client_uri`. Nome declarado não prova nada; o que distingue com alguma garantia é o `redirect_uri` (domínio `claude.ai` para o app; `localhost` para o Claude Code). A rodada com CIMD ligado (`start.sh --cimd`) fica para a parte 2, junto com Codex e ChatGPT; ela diz se o Claude passa a mandar `client_id` em URL do fornecedor, o que provaria identidade.

**P3. ChatGPT Pro só lê, e o servidor precisou garantir?** Parte 2, com conta emprestada (Wilson). O servidor já emite só `poc:read` para cliente identificado como ChatGPT, provado em teste automatizado. Decisão de Lucas Scholz (06/10): se o ChatGPT der trabalho, sai da fatia 1 e vai para a v2 com o GPT do Wilson.

**P4. `laravel/mcp` + Passport funcionam sem gambiarra?** Funcionam no caminho padrão. As regras da casa pediram 15 ajustes pequenos (lista em `docs/poc-mcp/README.md`): escopos próprios (o pacote só traz `mcp:use`), servidor decidindo o escopo pelo papel, audiência RFC 8707, `iss`, PKCE só S256, loopback sem porta, CIMD mínimo, CSP `form-action` liberando o redirect do assistente, `Inertia::location` no login, 401 em vez de 302 no `/mcp`. Nenhum exige trocar de pacote. Três se apoiam em detalhe interno de biblioteca (métodos estáticos do `Registrar`, `aud[0]` como `client_id`, `getClientEntity` lendo a requisição): o B8 precisa de teste que acuse quando o pacote mudar.

**Confirmação antes de escrever (IA9):** nem o Claude app nem o Claude Code pediram confirmação antes de `anotar`, mesmo com a ferramenta marcada como escrita e destrutiva (`readOnlyHint=false`, `destructiveHint=true`) e com "Confirme com o usuário antes de chamar" na descrição. Confirma o que a IA9 já dizia: a segurança não pode depender da confirmação do assistente. Consequência para o B8: toda escrita pela IA precisa ser reversível e rastreável (mover tem histórico e volta; card criado por engano se arquiva ou exclui; horas se corrigem; comentário o autor exclui), e a descrição das ferramentas de escrita deve pedir a confirmação mesmo assim, por ser barato. Nada de ferramenta de exclusão (IA8).
