0. CONVENÇÕES DESTE ARQUIVO
=====================================================================
Banco
- Motor: MySQL 8 (stacks/laravel-inertia.md), DECIDIDO em 24/09 (DB-01), em container próprio na
  VPS do DaaS, separado do Postgres do Supabase (D-GER-14). Vale o que está marcado [MY]; as notas
  [PG] ficam só como registro da alternativa descartada.
- Collation: utf8mb4_0900_ai_ci (sem acento e sem caixa), DECIDIDO (DB-02).

Nomes
- Inglês, plural, snake_case. FK = <singular>_id.
- Tabelas de Projetos e CRM sem prefixo, mas sem nome ambíguo entre domínios:
  board_stages (quadro) × funnel_stages (funil); task_* × lead_*.

Colunas padrão (omitidas nas tabelas abaixo para não repetir)
- id                bigint unsigned pk auto_increment
- created_at        timestamp  not null
- updated_at        timestamp  not null
- Exceção: tabelas de log imutável (audit_logs, *_movements, ai_tool_calls) só têm created_at.

Tipos
- timestamp  = data e hora em UTC. [MY] datetime (NÃO o tipo TIMESTAMP do MySQL, que acaba em
               2038-01-19: contrato e compromisso futuros passam disso), gravado em UTC.
               No Laravel: dateTime() em vez de timestamp(), inclusive em created_at/updated_at.
               [PG] timestamptz.
- date       = data de negócio sem hora (worked_on, due_on, feriado). Calculada com fuso explícito America/Sao_Paulo.
- money      = decimal(15,2). Nunca float.
- hours      = decimal(6,2). Horas decimais, sem arredondar para dia (RN-PRJ-15).
- cnpj       = char(14), só dígitos.
- text curto = varchar com tamanho; texto livre = text.

Desativar, não excluir (banco.md §4, RN-NUC-02)
- deactivated_at timestamp null + deactivated_by fk users null (on delete restrict).
- "Ativo" = deactivated_at is null, numa consulta única (scope global) que toda tela e ferramenta MCP herda.
- Vínculos que entram e saem (alocação, atribuição, PR, item de pacote) usam removed_at/removed_by:
  o vínculo antigo fica para o histórico, nunca é apagado (RN-PRJ-29).

Único "só entre os ativos" (padrão U1)
- [PG] índice único parcial: unique (a, b) where removed_at is null.
- [MY] não tem índice parcial. Usa coluna gerada:
    active_key tinyint GENERATED ALWAYS AS (IF(removed_at IS NULL, 1, NULL)) STORED
    unique (a, b, active_key)        -- NULL não colide, então só os ativos travam
- Onde aparece "unique U1 (a, b)", é este padrão.

Domínios
- (fechado)     = valores fixos, semeados pela migração, sem tela de edição. Colunas: id, slug, label.
                  O código compara por slug, nunca por id nem por label.
- (cadastrável) = lista que o Administrador ou o gestor edita (D-GER-05). Colunas: id, slug null, label,
                  sort_order, deactivated_at/by. Item usado nunca é excluído, só desativado.
- "Papel" (role) = domínio fechado por trás de uma lista cadastrável. O usuário renomeia a etapa
  à vontade; indicador é calculado pelo papel (RN-PRJ-13). Mesmo padrão no funil e no pacote.

onDelete
- Padrão: restrict. cascade só em filho que não existe sem o pai E cujo pai nunca é excluído
  depois de usado (na prática, o cascade só dispara em registro nunca usado, banco.md §4).
- Nenhum cascade apaga arquivo: exclusão de pai com attachments passa pelo Service, que limpa o storage.
- [MY] Coluna usada em CHECK não pode ter FK com cascade ou set null (erro 3823). Toda FK que
  aparece num CHECK deste arquivo é restrict.

Auditoria
- Toda escrita de qualquer módulo grava 1 linha em audit_logs (tabela única, D-GER-16, RN-NUC-04),
  com canal (tela, ia:*) e, se veio da IA, a autorização (RN-IA-03).
- Histórico que o requisito pede ("editar fica no histórico": RN-CRM-03, RN-CRM-14, RN-PRJ-20, RN-PRJ-29)
  mora em audit_logs. Só ganha tabela própria o histórico que vira INDICADOR (movimentos de etapa),
  porque precisa de consulta rápida e colunas tipadas.

Marcação de entrega
- [v1]  entra na primeira versão.
- [v1*] tabela criada na v1 porque o dado precisa ser gravado desde o início, mas a tela é v1+
        (ex.: retrabalho e produtividade: F-PRJ-01, F-PRJ-17).
- [v1+] pode ficar para depois sem perder dado.
- [?]   depende de resposta (seção 7).

#  6. DECISÕES (propostas; valem quando o Lucas Alencar aprovar)
#####################################################################
6.1  Sistema interno single-tenant: NÃO há enterprise_id em toda tabela como no template. O escopo
     é por papel + vínculo (alocação no projeto, dono do lead, contato do cliente). O único escopo
     "por empresa" é o do contato externo (futuro portal), derivado do registro, nunca do request.
6.2  Direção das FKs: Projetos → Platform, CRM → Platform. Platform não aponta para módulo.
     Projetos e CRM não se apontam (D-GER-15). Chamados → Platform + tasks.
6.3  Etapas livres com papel fixo em três lugares (quadro, funil, pacote): o usuário renomeia,
     cria e remove (D-GER-05); os indicadores leem o papel. Os movimentos gravam SNAPSHOT do papel,
     então renomear ou trocar papel de etapa não reescreve o passado (RN-PRJ-29).
6.4  Histórico de edição mora em audit_logs (D-GER-16). Tabela de movimento própria só onde o
     histórico é indicador (task_stage_movements, lead_stage_movements).
6.5  Chave da tarefa: key gravada e imutável + contador por projeto com lockForUpdate + unique
     (project_id, number). Consequência: key_prefix congela após a primeira tarefa.
6.6  Contato de lead separado de contato de cliente, para não criar FK do Núcleo para o CRM.
     A conversão copia (e liga lead_contacts.client_contact_id). Custo: duas tabelas parecidas.
6.7  Estimativa e horas por pessoa, sem coluna de total: previsto e realizado são somas derivadas.
     Única "foto" gravada: tasks.due_on (data prevista), porque depende de carga e feriados do dia
     do cálculo (RN-PRJ-17).
6.8  time_entries.contract_id é copiado e congelado na gravação: banco de horas não muda sozinho.
6.9  Vínculos (membro, atribuição, PR, item de pacote, estimativa) nunca são apagados: removed_at.
     Cadastros (cliente, contato, usuário, contrato, lead) desativam: deactivated_at/by.
     Exclusão real só de registro nunca usado, por admin, via Service que limpa arquivos.
6.10 Domínio que o código usa em regra = tabela fechada comparada por slug. Domínio que o usuário
     edita = tabela cadastrável; se o código depende de um item (task_types.support,
     appointment_types.follow_up), o slug desse item é protegido contra desativação.
6.11 Flags internas sem rótulo de tela (outcome, kind, direction, provider) = varchar + CHECK.
6.12 Fuso: banco em UTC, exibição e cálculo de data de negócio em America/Sao_Paulo.
6.13 Tudo que pode ser escrito pela IA grava audit_channel_id na própria linha também (tarefa,
     tratativa, compromisso, hora): filtro "o que a IA fez" sem join no audit_logs.
6.14 Nenhuma tabela guarda chave de API de provedor de IA ("O que não pode"). Credencial de IA é só
     o token OAuth emitido pelo próprio Hub.
