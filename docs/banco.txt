0. CONVENÇÕES
=====================================================================
Princípio desta versão: cada tabela e cada coluna existe porque uma regra do requisito lê ou grava
aquele dado. O motivo está ao lado (RN-/D-/F-). Sem motivo, não entra.

Banco
- MySQL 8, container próprio na VPS do DaaS, separado do Supabase (DB-01, D-GER-14).
- Collation utf8mb4_0900_ai_ci: nome com unique ignora acento e caixa (DB-02).

Nomes
- Inglês, plural, snake_case. FK = <singular>_id.

Colunas padrão (omitidas abaixo)
- id          bigint unsigned pk auto_increment
- created_at  datetime not null
- updated_at  datetime not null
- Exceção: log imutável (audit_logs, task_stage_movements, ai_tool_calls) só tem created_at.

Tipos
- datetime = data e hora em UTC. NÃO usar o tipo TIMESTAMP do MySQL (acaba em 2038-01-19).
             No Laravel: dateTime(), inclusive em created_at/updated_at.
- date     = data de negócio sem hora, calculada no fuso America/Sao_Paulo.
- hours    = decimal(6,2). Horas decimais, sem arredondar para dia (RN-PRJ-15).
- money    = decimal(15,2).

Quem fez e quando
- Fica em audit_logs (tabela única, D-GER-16, RN-NUC-04): usuário, canal, antes/depois.
- Coluna *_by só existe quando uma regra lê a pessoa: deactivated_by (banco.md §4), validated_by
  (teste cruzado, RN-PRJ-26), tested_by (roteiro do QA), moved_by (histórico da tarefa, cenário de
  aceite de IA), owner_id (RN-CRM-05), manager_id (RN-PRJ-05).
- Nada de created_by, added_by, assigned_by, estimated_by: é audit_logs.

Derivar, não guardar
- Não há coluna de cache. Status que se deduz de outra coluna é deduzido (lead ganho = etapa de
  resultado "won"; sprint em andamento = hoje entre as datas; contrato ativo = hoje entre as datas).
- Exceções, cada uma com regra: tasks.key (busca direta "SGM-17", imutável), tasks.due_on e
  sprint_members.daily_hours (fotos que a RN-PRJ-17 manda não recalcular).

Desativar, não excluir (banco.md §4, RN-NUC-02)
- Cadastro com histórico: deactivated_at datetime null + deactivated_by fk users null.
- "Ativo" = deactivated_at is null, numa consulta única que toda tela e ferramenta MCP herda.
- Etapa e estado configuráveis que já foram usados: archived_at (RN-PRJ-29).
- Vínculo (alocação, contato do lead) é removido de verdade; o histórico está em audit_logs.

Domínios
- (fechado)     valores fixos, semeados, sem tela de edição. Colunas: id, slug, label.
                O código compara por slug.
- (cadastrável) lista que o usuário edita (D-GER-05). Colunas: label + deactivated_at/by, mais slug
                só nos itens de que o código depende.
- Flag interna sem rótulo de tela = varchar + CHECK.

onDelete
- Padrão: restrict. cascade só em filho que não existe sem o pai (e o pai só é excluído se nunca
  foi usado). Nenhum cascade apaga arquivo: exclusão com anexo passa pelo Service.
- MySQL: coluna usada em CHECK não pode ter FK com cascade ou set null (erro 3823).

     pacote ficam em audit_logs: nenhuma regra pede a lista histórica em tabela.
6.8  Critério de aceite e item do roteiro são a mesma linha: 1 critério = 1 item (F-PRJ-14).
6.9  Chave da tarefa: key gravada + contador atômico (T4) + unique (project_id, number).
